# 阶段五：四角色模拟审稿、Rebuttal 修回与复现包审计（v1.0 完整版）

本模块提供投稿前“压力测试”及返修应对工作流，涵盖**四角色审稿批判、致命伤分级、结构化 Rebuttal 逐条回复，以及 AEA / 国内权威期刊复现包审查标准**。

---

## 一、投稿前四角色模拟审稿协议（Four-Role Referee Attack）

在提交论文或完成初稿阶段，必须切换至冷峻的匿名审稿人视角，依次从四个专业角色展开只读穿透式审查，严禁自我宽容或掩盖短板：

1. **角色 A：执行编辑 / 学科主编（Co-Editor）——立意重要性与边际贡献审计**
   - 审视：读完前 3 页是否已明确知道“研究问题是什么、数据与识别靠什么、核心发现有多大、比最接近论文推进在哪一步”？是否存在“换地区、换年份、换指标名称”的伪创新或仅对小众人群有效却大谈宏大政策的脱节？
2. **角色 B：计量与识别专家（Econometrician）——识别漏洞与统计推断审计**
   - 审视：识别假设有无制度反例？是否存在交错 TWFE 负权重、隐蔽的坏控制变量（Bad Controls）、处理后中介三步法、未论证的 `ln(1+y)` 取对数、过低的第一阶段 $F$ 值（低于 Lee et al. $104.7$ 基准且未报 $tF$/AR 区间）、或错误的高层盲目聚类（Abadie et al., 2023）与少簇偏误？
3. **角色 C：领域与制度专家（Field Expert）——机制竞争与现实解释力审计**
   - 审视：是否存在未排除的竞争性机制故事？作者把观测现象归因于所喜欢的机制时，能否通过理论预测的交叉异质性或通道阻断切分加以区分？估计的经济量级是符合既有文献常理，还是存在脱离现实的夸张（例如小干预带来巨额 GDP 或生产率跃迁）？
4. **角色 D：数据与复现编辑（Data & Replication Editor）——可复现性与数字自洽审计**
   - 审视：文字、表格、图注中的样本量 $N$、均值、系数和转换百分比是否逐一与 Stata `.log` 对齐？跨列样本流失有无交代？脚本有无硬编码路径、UTF-8 BOM、`capture` 掩盖错误或未标明随机种子的随机过程？

### 审稿问题三级严重度定级

| 级别 | 判定标准 | 处理要求 |
| :--- | :--- | :--- |
| **Fatal（拒稿级致命伤）** | 核心识别假设存在明显反例、存在严重坏控制或错误估计器导致主结论反转、关键数字与脚本/逻辑自相矛盾、或样本无法复现 | **必须立即暂停投稿**，重返阶段三重新设计识别、重构变量或收缩主张边界 |
| **Major（大修级核心隐患）** | 缺乏必要敏感性界限（如 `honestdid`/AR 区间）、机制检验仅停留在相关描述、或部分表注单位与聚类层级交代不清 | 返修或投稿前**必须补齐实证检验与文字重构** |
| **Minor（小修级体例与表达）** | 图表排版未满足三线表规范、局部术语不统一、个别语句存在套话或附录索引微瑕 | 逐一核改文字与图表格式后即可定稿 |

## 二、审稿意见回复（Response-to-Referees / Rebuttal）实战规范

收到审稿人或指导教师修改意见后，严格按以下四步组织回复信（Response Letter），做到不回避、不狡辩、不敷衍：

### 1. 致编辑与审稿人的总括信（Cover Letter）

- 简明致谢，用 1 个紧凑清单概述本轮修订所完成的**三至五项最核心增量工作**（例如补充了哪项识别敏感性、更换了哪个稳健估计器、新增了何种机制检验、核正了哪组数据边界），并说明所有修改在正文中的位置标记方式（如蓝字/修订模式）。

### 2. 逐条拆解与结构化回复模板

对每位审稿人的每一条意见逐一编号（如 `R1.1`、`R1.2`），严禁将多条尖锐意见合并模糊带过。每条回复固定采用四段结构：

```markdown
**[R1.3] 审稿人原文完整摘录：**
> （一字不差引用审稿人原话，即便意见很长或带批评性）

**回复结论（1 句话先亮态度与修改结果）：**
我们完全同意/高度重视审稿人关于……的意见，已在修订稿第 X 节（Table X / Appendix Table AX）补充了……检验，核心估计量保持在……且该补充说明已嵌入正文第 X 页。

**技术细节与新增证据：**
（给出确切的检验方法、样本量变化、具体系数、标准误与物理含义解释，并在需要时直接把精简小表贴入回复信中，使审稿人无需反复翻阅附录即可完成判断。）

**正文精确修订定位：**
（给出修订后的节号、页码及核心改写段落摘录。）
```

### 3. 如何专业有理地婉拒不当修改要求（Polite Pushback）

当审稿人要求做违反现代计量原则的操作时（例如：在 DID 主回归中加入内生处理后控制变量、要求使用已被否定的三步法中介检验、或要求在仅有 15 个聚类簇时盲目使用常规聚类），遵循“**先尊重问题本质 → 用计量文献与附加附录检验回应 → 坚持主表干净**”原则：

1. 明确表示理解审稿人背后的经济关切（例如担心机制解释或行业同步冲击）；
2. 引述权威方法文献解释为何将该内生变量直接放入**基准主表**会引入对撞偏误或过度控制偏误（例如引用 Angrist & Pischke 或 Jiang 2022），同时改用合规方式（如前定基线调节交互或直接因果机制回归）在主文回答该关切；
3. 若有必要展示对照，可将按审稿人要求强行加入的回归附在**回复信或在线附录**供参考并明确标注其偏误边界，保持主表识别干净。

## 三、复现包（Replication Package）发布审计与五项终审清单

在对外发布或随刊提交代码与数据时，对标 **AEA Data and Code Availability Policy** 与国内顶刊复现包标准：

### 1. 标准复现目录结构

```text
replication_package/
├── README.md                  # 数据来源、获取权限、软硬件环境、主脚本运行耗时与表图映射表
├── 00_master.do               # 唯一总控脚本（相对路径、自动依次调用清洗、主估计与导出脚本）
├── code/
│   ├── 01_build_data.do       # 原始数据只读读取、审计、清洗、构造分析样本
│   ├── 02_main_tables.do      # 生成正文主表
│   ├── 03_figures.do          # 生成正文主图
│   └── 04_appendix.do         # 生成在线附录表图
├── data/
│   ├── raw/                   # 只读原始数据或脱敏说明文件（不可覆盖）
│   └── analysis/              # 清洗后锁定的共同分析样本
└── output/
    ├── tables/                # 自动导出的 .tex / .txt 表格
    ├── figures/               # 自动导出的高分辨率白底 .png / .pdf 图形
    └── logs/                  # 完整带时间戳的运行文本 .log 文件
```

### 2. 投稿前五项与脚本自动化终审清单

1. **目标参数与识别一致**：写明核心参数（关联、ATT、ITT 或 LATE）及依赖假设，已彻底排查并剔除处理后坏控制变量。
2. **数据与共同样本透明**：`isid` 与 `assert` 校验通过，原始数据只读保存，跨列模型样本变化原因交代清楚。
3. **推断、稳健性与经济意义到位**：聚类层级符合分配与抽样结构，稳健性围绕具体威胁靶向设置，正文已汇报相对均值/标准差或成本收益量级。
4. **脚本自动化巡检全绿**：在项目根目录或 `examples/` 运行工具包自检，确保无 UTF-8 BOM、无硬编码个人路径、无 `capture` 掩盖关键回归、且 `.log` 零报错完成：
   - 日志审计：`python scripts/audit_stata_log.py <path_to_log>`
   - 目录规范审计：`python scripts/check_replication_package.py <package_dir> --strict`
5. **正文与输出逐字咬合**：全部表图均由脚本自动导出，文本引用与脚本输出逐字一致，分清百分比与百分点、关联与因果、以及不显著与零效应，并完整核对 [research_contract_template.md](../resources/research_contract_template.md) 末段数字台账。
